# Rak Buku Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PWA rak buku PDF pribadi yang bisa dibaca offline. Posisi baca tersimpan otomatis sampai bagian dalam halaman, dan disinkronkan antar perangkat lewat Google Drive milik pemilik.

**Architecture:** Situs statis (HTML + modul ES, tanpa build step) di GitHub Pages, dengan pdf.js lokal dan service worker untuk offline. Setiap perangkat menyimpan status miliknya sendiri (`status-<deviceId>.json`) di folder Drive "Rak Buku". Status dari semua perangkat digabung dengan fungsi murni. Cloudflare Worker kecil hanya menukar dan memperbarui token Google (refresh token terenkripsi disimpan di perangkat, Worker tidak menyimpan apa pun).

**Tech Stack:** JavaScript modul ES, pdf.js 4.10.38 (`vendor/`), IndexedDB, Service Worker, Google Drive API v3 (scope `drive.file`), Cloudflare Workers + WebCrypto, `node:test` (Node 26) untuk unit test.

**Spec:** `docs/superpowers/specs/2026-11-27-rak-buku-design.md`

## Global Constraints

- Hanya PDF. Teks antarmuka berbahasa Indonesia.
- Tanpa dependensi npm runtime. Tes memakai `node --test` saja.
- Scope Google hanya `https://www.googleapis.com/auth/drive.file`.
- Worker tidak menyimpan data. Tanpa database dan tanpa cookie. Refresh token dienkripsi AES-GCM dengan secret `SEAL_KEY`.
- Kembali ke PWA lewat fragment `#auth=<blob>`, lalu fragment langsung dihapus dari URL.
- Prefetch: file yang dibuka ditambah **2** file berikutnya dalam seri, hanya saat online.
- Rendering: hanya halaman di layar ±2 halaman yang memakai kanvas.
- Posisi baca disimpan lokal dengan debounce **1 detik** setelah scroll berhenti, dan juga pada `pagehide`/`visibilitychange`.
- Sinkronisasi: saat aplikasi dibuka, `visibilitychange` ke hidden, event `online`, dan setiap **30 detik** selama membaca.
- Menghapus seri dari Drive = memindahkan ke Trash Drive, selalu lewat konfirmasi.
- Kategori: `komik`, `novel`, `lain` (label: Komik, Novel, Buku lain).

**Penyesuaian dari spec (keputusan perencana):** di file status, record file punya `id` (uuid lokal) dan `driveId` (null sampai upload selesai). Progres dan bookmark merujuk ke `fileId`, bukan `fileIdx`. Alasannya, indeks bisa bergeser saat batch ditambah dari perangkat lain. Penggabungan file dilakukan per `id`.

## Review Focus

1. **Aplikasi dimatikan iOS di tengah scroll.** Posisi harus sudah tersimpan (debounce 1 detik ditambah `pagehide`). Dites di Task 7.
2. **PDF rusak atau terkunci password.** Tampilkan pesan pada kartu atau saat menambah, dan rak tidak boleh ikut rusak. Dites di Task 6.
3. **Upload file besar putus di tengah jalan** (sinyal hilang atau aplikasi ditutup). Upload dilanjutkan dari byte terakhir, bukan diulang dari awal, dan file lokal tidak hilang. Dites di Task 9.
4. **Membuka buku yang belum di-download saat offline.** Tampilkan pesan yang jelas "Belum ada di perangkat, sambungkan internet", tanpa layar kosong. Di akhir batch yang batch berikutnya belum ada, tampilkan pesan yang sama. Dites di Task 7.
5. **Login kedaluwarsa atau dicabut** (`invalid_grant`). Sinkronisasi berhenti dengan banner "Login ulang", dan data lokal serta antrean upload tetap utuh. Dites di Task 9.

### Task 1: Repo dan enkripsi Worker

**Files:**
- Create: `package.json`, `.gitignore` (`contoh/`, `node_modules/`, `.wrangler/`), `worker/seal.js`, `worker/worker.js`, `worker/wrangler.toml`
- Test: `test/seal.test.js`, `test/worker.test.js`

**Interfaces:**
- Produces: `seal(text: string, keyB64: string): Promise<string>` (base64url `iv|ciphertext`), `unseal(blob: string, keyB64: string): Promise<string>` (melempar error kalau blob diubah atau kunci salah). Worker `export default { fetch(req, env) }` dengan env `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `SEAL_KEY`, `APP_URL`.
- Endpoint: `GET /login` → 302 ke `accounts.google.com/o/oauth2/v2/auth` (`response_type=code`, `access_type=offline`, `prompt=consent`, scope drive.file, `redirect_uri=<origin worker>/callback`). `GET /callback?code=` → tukar di `oauth2.googleapis.com/token`, lalu 302 ke `${APP_URL}#auth=<seal(refresh_token)>`. Jika gagal: 302 ke `${APP_URL}#auth-error=<pesan>`. `POST /token` body `{blob}` → `{access_token, expires_in}`. Jika `invalid_grant`: 401 `{error:"relogin"}`. CORS hanya untuk origin `APP_URL`, termasuk preflight `OPTIONS`.

### Task 8: Daftar isi, bookmark, mode malam, zoom

**Files:**

Perilaku:
- **Daftar isi:** daftar file seri (untuk seri banyak file) dan outline tiap file. Ketuk item untuk melompat ke halaman itu (offset 0).
- **Bookmark:** "Tandai di sini" menyimpan posisi sekarang dan meminta catatan (boleh kosong). Daftar bookmark seri ditampilkan sebagai `Batch i · hal p` + catatan. Ketuk untuk melompat, geser atau tekan tombol hapus untuk menghapus (tombstone).

Setelah jari diangkat, zoom = clamp(zoom×s, 1, 4), layout dibangun ulang, scroll dipulihkan ke `positionAt` sebelum zoom, dan scroll horizontal diaktifkan saat zoom > 1. Ketuk dua kali untuk kembali ke zoom 1. Pastikan `<meta viewport>` memakai `user-scalable=no` supaya Safari tidak ikut men-zoom halaman.

- [ ] **Step 2: Verifikasi di browser:** lompat dari daftar isi novel, buat 2 bookmark lalu reload (keduanya masih ada) dan hapus satu. Mode malam dan balik warna harus bertahan setelah reload. Zoom dua kali lipat lalu scroll: posisi yang tersimpan tetap benar setelah reload.
